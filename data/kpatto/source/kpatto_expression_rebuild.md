## 1. 스키마 변경

```sql
ALTER TABLE kp_expressions ADD COLUMN compare TEXT NULL;
ALTER TABLE kp_expressions ADD COLUMN episodes JSONB NULL;
```

- `compare` — 비슷한 표현과의 차이 설명(영문). 값이 없으면 팝업에서 해당 칸을 렌더링하지 않는다.
- `episodes` — 이 표현이 등장하는 EP 번호 배열. 예: `[41]`, `[22,61,84,91,96]`

---

## 2. exposure 데이터 전량 삭제

시즌1에서 exposure 개념을 폐기한다.

```
DELETE FROM kp_dialogue_expressions WHERE role = 'exposure';
```

- `role` 컬럼 자체는 유지. 앞으로 모든 행은 `'focus'`.
- `ep_pattern_map.md`의 `⚠ 없음` 행은 전부 무시한다.

## 6. sync 스크립트 작성

`scripts/sync-episode.ts` **하나만** 만든다. 화별 일회용 스크립트(`_setup-epNN.ts` 등)는 만들지 않는다.

```
npx tsx scripts/sync-episode.ts --ep 1
npx tsx scripts/sync-episode.ts --ep 1-10
```

입력은 대화창에서 확정된 텍스트 대본이며, 형식은 다음과 같다.

```
EP01 | 카페에서
[컷1]
  에마(생각): 와, 예쁘다.
        EN: Wow, it's beautiful.
[컷3]
  에마: 음… 저기요, 이거 뭐예요?
        EN: Um... excuse me, what is this?
  ▸ ~뭐예요? → "뭐예요?"
```

- `▸` 줄이 하이라이트 지정. 화살표 뒤 따옴표 안 문자열이 `matched_text`.
- `(생각)` 표시는 말풍선 타입 `thought`(구름형). 없으면 `speech`.

### 동기화 동작

| 대상 | 처리 |
|---|---|
| `kp_dialogues` | 해당 EP 행 삭제 후 재삽입 (컷·순서 유지) |
| `kp_bubbles` | **좌표 유지**, 텍스트만 교체. 개수 증감 시 기본 좌표로 생성·삭제 |
| `kp_dialogue_expressions` | `▸` 지정만 `role='focus'`로 연결 |

### 안전장치 (필수)

1. 실행 전 `kp_expressions` 행 수가 **323**이 아니면 에러로 중단하고 안내:
   `"핵심표현 DB가 아직 재구축되지 않았습니다."`
2. `▸`에 나온 표현이 `kp_expressions`에 없으면 에러로 중단. 표현명과 EP 번호 출력.
3. `matched_text`가 대사 문자열에 **정확 일치**하지 않으면 에러로 중단. 해당 대사 줄 출력.
   부분 매칭 금지 — `"있어요?"`는 매칭, `"있어요"`만으로는 매칭 안 함.
4. 같은 표현이 한 화에 2회 이상 나오면 **첫 등장에만** 연결.
5. 하나라도 실패하면 그 배치 전체 롤백. 부분 반영 금지.

## 7. 팝업 렌더링

컴포넌트는 **한 종류만** 사용한다. 문법과 표현을 구분하지 않는다.

| 위치 | 필드 |
|---|---|
| 제목 | `pattern_ko` |
| 부제목 | `literal_en` — 설명문이 아니라 영어 대응 표현 |
| 본문 | `usage_en` |
| 예문 | `examples[]` 3개 (ko 위 / en 아래) |
| 비교 | `compare` — **값이 있을 때만 표시** |
| 하단 | 닫기 버튼 |

- 하이라이트: `#D4873A`, 굵게, 점선 밑줄
- 해당 말풍선: 테두리 `#D4873A` + 배경 `#FFF8F0`
- 팝업을 닫으면 스크롤 위치 복원
